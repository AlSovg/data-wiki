# Сбор требований

Черновик для согласования. Пункты «Решение» — предложения по умолчанию.

## 1. Форматы Markdown

| Элемент | Поддержка | Как используется |
|---|---|---|
| CommonMark (заголовки, списки, ссылки, цитаты, код) | да | базовый парсинг |
| GFM: таблицы, списки задач, зачёркивание | да | текст попадает в индекс |
| YAML frontmatter (`---`) | да | источник метаданных |
| Fenced code blocks | да | индексируются с пониженным весом, язык сохраняется |
| Inline-HTML | нет | вырезается при нормализации (безопасность и шум в индексе) |
| Wiki-ссылки `[[...]]`, `#тег` в тексте | опционально | `#тег` можно подтягивать в теги, если хватит времени |

**Анализ структуры:** дерево заголовков (h1–h6), заголовок документа (frontmatter `title` → первый h1 → имя файла), число слов, символов, блоков кода, ссылок, время чтения.

**Валидация и нормализация:**
- кодировка UTF-8, отклонять бинарные файлы и файлы больше лимита (по умолчанию 1 МБ);
- нормализация переводов строк (`\n`), Unicode NFC, обрезка пробелов;
- ошибки frontmatter не роняют импорт: невалидный YAML → документ принимается без метаданных + предупреждение в ответе;
- дубликаты определяются по хэшу нормализованного содержимого.

**Требование к парсеру:** соответствие CommonMark + GFM, доступ к дереву токенов/AST (для заголовков и блоков кода), расширение для frontmatter. Конкретная библиотека выбирается вместе со стеком.

## 2. Метаданные

| Поле | Тип | Источник | Примечание |
|---|---|---|---|
| `id` | UUID | система | |
| `title` | строка | frontmatter / h1 / имя файла | обязательно после нормализации |
| `tags` | список строк | frontmatter | нижний регистр, без дублей, до 20 |
| `category` | строка | frontmatter | одна категория на документ |
| `author` | строка | frontmatter, иначе имя пользователя | |
| `created_at`, `updated_at` | timestamp | система (frontmatter `date` допускается) | |
| `version` | целое | система | растёт при каждой правке |
| `owner_id` | ссылка на пользователя | система | изоляция данных |
| `size_bytes`, `word_count` | числа | анализ | для статистики |

Пример frontmatter:

```yaml
---
title: Как работает BM25
tags: [search, ranking]
category: algorithms
author: Александр
---
```

**Решение:** теги — сущность со связью многие-ко-многим (фильтрация и облако тегов); категория — одно значение на документ, без иерархии; версии хранят полный текст + метаданные.

## 3. Методы скоринга

| Метод | Роль | Детали |
|---|---|---|
| **BM25** | основной | k1=1.2, b=0.75 (значения по умолчанию, настраиваемые) |
| **TF-IDF** | базовый / для сравнения | tf с логарифмическим сглаживанием, косинусная близость не нужна — сумма tf·idf по терминам запроса |
| **Встроенный FTS выбранной СУБД/движка** | внешний ориентир для сравнения | зависит от стека, опционально |
| **Гибрид** | доп. пункт ТЗ | взвешенная сумма нормализованных (min-max) оценок методов, веса задаёт пользователь |

**Поля и буст:** заголовок ×3, заголовки разделов ×2, теги ×2, тело ×1, код ×0.5 (веса настраиваются).

**Токенизация:** нижний регистр, разбиение по не-буквам/цифрам, стоп-слова RU+EN, стемминг Snowball для русского и английского.

**Индекс:** инвертированный индекс с частотами терминов и длинами документов, статистики корпуса (N, avgdl) пересчитываются инкрементально; на индекс влияет только актуальная версия документа.

**Подсветка:** сниппеты вокруг совпавших терминов, обёртка `<mark>`.

**Как сравниваем методы:** небольшой набор эталонных запросов на демо-корпусе, метрики P@k / nDCG — материал для отчёта.

## Импорт

Режимы: один файл, несколько файлов, папка, архив. Для папки и архива принимаются только `.md`, остальные файлы пропускаются с предупреждением; исходный путь внутри папки/архива сохраняется в метаданных; лимит на файл — 1 МБ. Ответ содержит отчёт по каждому файлу: принят, отклонён (причина) или дубликат.

## Решения

- Стемминг для русского и английского включён по умолчанию, отключается в настройках.
- Гибрид: нормализация min-max с пользовательскими весами; RRF — опциональное дополнение.

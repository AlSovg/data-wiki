# Скоринг: BM25, TF-IDF, гибрид

Формулы BM25 и TF-IDF сверены с исходниками Lucene 10.5.1 (`BM25Similarity`, `ClassicSimilarity`, `TFIDFSimilarity`, `Similarity`). Что именно требуется от проекта (настройка Lucene или собственная реализация) — вопрос 2 в `docs/questions-for-case-author.md`.

## Обозначения

| Символ | Значение |
|---|---|
| `q` | запрос, набор термов `t` после анализа (тот же анализатор, что при индексации) |
| `N` | число документов с непустым полем (`docCount` поля) |
| `n_t` | число документов, где терм `t` встречается в поле (`docFreq`) |
| `f(t,d)` | частота терма в поле документа `d` |
| `dl` | длина поля `d` в термах |
| `avgdl` | средняя длина поля по индексу |
| `boost` | множитель поля (см. ниже) |

Оценка считается **по полю**, итог по документу — сумма по полям с бустами. Статистики (`N`, `n_t`, `avgdl`) берутся по каждому полю отдельно.

## BM25

Метод по умолчанию. Параметры: `k1 = 1.2`, `b = 0.75` (настраиваемые).

```
idf(t)        = ln(1 + (N − n_t + 0.5) / (n_t + 0.5))
tf_norm(t,d)  = f / (f + k1 · (1 − b + b · dl / avgdl))
score_BM25    = Σ_{t ∈ q}  boost · idf(t) · tf_norm(t,d)
```

- Множителя `(k1 + 1)` в числителе (классическая форма Робертсона) в Lucene нет: он убран, порядок документов не меняется, шкала оценок другая.
- `idf` всегда положителен (форма `ln(1 + …)`), поэтому частые термы не дают отрицательный вклад.
- `k1` задаёт насыщение по частоте, `b` — степень нормализации по длине (`b = 0` — длина игнорируется).

## TF-IDF

Реализация `ClassicSimilarity` (базовый метод для сравнения).

```
idf(t)         = ln((N + 1) / (n_t + 1)) + 1
tf(t,d)        = √f
lengthNorm(d)  = 1 / √dl
score_TFIDF    = Σ_{t ∈ q}  boost · idf(t) · tf(t,d) · lengthNorm(d)
```

- Косинусной близости и нормировки запроса нет: это сумма по термам запроса (`queryNorm` и `coord` в современном Lucene удалены).
- В `requirements.md` для TF-IDF указано «tf с логарифмическим сглаживанием» — Lucene использует `√f`. Если автор кейса потребует собственную реализацию, можно взять `1 + ln f`; для Lucene-варианта остаётся `√f`. Расхождение надо снять после ответа на вопрос 2.

## Длина документа и нормы

Длина поля кодируется при индексации одним байтом (`SmallFloat.intToByte4`, метод `Similarity#computeNorm`) — это приближение, поэтому `dl` в обеих формулах округлён. Из-за общей кодировки один индекс обслуживает оба метода без переиндексации (см. `system-design.md`, раздел 4). Условия: не переопределять `computeNorm`, `discountOverlaps` одинаков — у `BM25Similarity` и `ClassicSimilarity` по умолчанию `true` (проверено в исходниках `Similarity()`; токены с нулевым приращением позиции не увеличивают `dl`).

## Поля и буст

| Поле | Буст |
|---|---|
| `title` | ×3 |
| `headings` | ×2 |
| `tags` | ×2 |
| `body` | ×1 |
| `code` | ×0.5 |

Запрос по нескольким полям — `BooleanQuery` из `TermQuery` по каждому полю с бустом (условие `SHOULD`), оценки суммируются. Поля `tags` в модели индекса не анализируются (`system-design.md`, раздел 4): совпадение по тегу используется как фильтр; если тег нужен как скоринговое поле, его надо индексировать как анализируемое — решить при реализации.

Так как `idf` и `avgdl` считаются по полю, короткое поле (`title`) получает большие `idf` для редких слов — это желательно, но делает оценки разных полей несопоставимыми по шкале; буст подбирается эмпирически на демо-корпусе.

## Гибрид

Взвешенная комбинация нормализованных оценок методов.

1. Каждый метод `m` выполняет тот же запрос с теми же фильтрами и возвращает top-`K` (`K = max(page · size, 100)`).
2. Нормализация min-max внутри списка метода:
   ```
   s'_m(d) = (s_m(d) − min_m) / (max_m − min_m)
   ```
   При `max_m = min_m` (один результат или равные оценки) все `s'_m = 1`.
3. Объединение по документам из объединения списков; отсутствующая оценка = 0:
   ```
   score_hybrid(d) = Σ_m  w_m · s'_m(d),    Σ w_m = 1
   ```
4. Веса: из запроса (`weights=bm25:0.7,tfidf:0.3`), иначе из настроек пользователя, иначе `bm25:0.5, tfidf:0.5`. Веса приводятся к сумме 1; отрицательные значения и нулевая сумма — ошибка 400.

Свойства и ограничения:
- Min-max чувствителен к выбросам: один очень высокий результат сжимает остальные к нулю. Альтернатива — RRF: `score(d) = Σ_m w_m / (60 + rank_m(d))`; опционально (решение автора кейса, вопрос 15).
- Документ, попавший в top-`K` только одного метода, получает нулевой вклад другого, даже если тот оценил бы его ненулевым. При `K` ≥ размера страницы влияние на первые страницы мало; полная оценка через второй метод возможна, но дороже.
- Нормализация зависит от набора кандидатов, поэтому оценки гибрида нельзя сравнивать между разными запросами.

## Реестр методов

Каждый метод реализует общий интерфейс (имя, выполнение запроса → список `(docId, score)`); реестр хранит методы по имени, гибрид ссылается на них по имени. Новый метод (например, `pg_fts`) добавляется регистрацией без изменения гибрида и API: список допустимых значений `method` отдаёт `GET /api/search/methods`.

## Оценка качества

Эталонные запросы и разметка релевантности на демо-корпусе, метрики P@k и nDCG@k для `bm25`, `tfidf`, `hybrid` — материал для отчёта; нужны ли они — вопрос 14.

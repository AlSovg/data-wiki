## Состояние проекта

Есть каркас Spring Boot (этап 1 `PLAN.md`); домен, парсер, индекс и поиск — по этапам плана. ТЗ — `AGENTS.md`, план — `PLAN.md`.

## Команды

- `mvn verify` — сборка и все тесты (нужен запущенный Docker: Testcontainers, первый прогон долгий из-за загрузки образов)
- `mvn test -Dtest=ИмяТеста` — один тест
- `cp .env.example .env && docker compose up -d --build` — весь стек; health: `GET /actuator/health` (через nginx, порт `HTTP_PORT`)
- Линтера нет. Новые команды добавляй сюда только когда они появились в репозитории.

## Что строим

Сервис личной базы знаний: принимает Markdown-документы, парсит и нормализует, индексирует, считает релевантность (TF-IDF, BM25, гибрид), даёт полнотекстовый поиск с подсветкой, кэширует запросы, хранит версии документов. Учебный проект с защитой — важны System Design, документация алгоритмов, тесты, docker-compose.

## Стек

Критерий выбора — пригодность для задачи (поиск/индексация/скоринг), а не удобство. Требования (`docs/requirements.md`) от стека не зависят.

**Утверждено (2026-09-30):** Java + Apache Lucene (10.x) как поисковое ядро. Причины: скоринг выбирается на уровне поля и запроса (`BM25Similarity`, `ClassicSimilarity` = TF-IDF, `MultiSimilarity`, `PerFieldSimilarityWrapper`), есть `RussianAnalyzer`/Snowball и модуль `highlighter`. Bleve (Go) отвергнут: модель скоринга задаётся глобально для индекса.

**Утверждённый стек (2026-09-30):**
- JDK 25 (LTS); Lucene 10.5.x требует JDK 21+
- Spring Boot 4.1 (4.0 поддерживается только до 2026-12-31)
- Maven
- PostgreSQL (источник истины: документы, версии, пользователи, права; произвольный frontmatter — в JSONB) + Flyway (миграции SQL-файлами)
- Redis (Spring Data Redis, Lettuce) — кэш поиска
- Spring Security — JWT
- commonmark-java (+ расширения tables, strikethrough, task-list, yaml-front-matter)
- springdoc-openapi — OpenAPI/Swagger
- JUnit 5 + Testcontainers — unit и интеграционные тесты
- Frontend: Vue 3 + Vite + TypeScript (SPA, статика через nginx). SSR/Nuxt не нужен: приложение закрыто авторизацией. HTML подсветки (`<mark>`) и превью Markdown санитизировать (DOMPurify)
- Docker + docker-compose, конфиг через переменные окружения

Индекс Lucene — на диске (том), это единственный экземпляр сервиса; ограничение указать в System Design. Индекс можно пересобрать из PostgreSQL.

Версии библиотек на момент выбора не фиксировались в `pom.xml` — проверять актуальные при создании каркаса.

## Архитектурные инварианты

- Скоринг — расширяемый: методы реализуют общий интерфейс и регистрируются по имени; гибрид = взвешенная комбинация методов с настраиваемыми весами.
- Версионирование документов: правка создаёт новую версию, индекс строится по актуальной.
- Данные изолированы по пользователю (JWT): каждый запрос к документам/поиску/кэшу фильтруется по владельцу, ключи кэша включают user id.
- Любое изменение документа инвалидирует связанные записи кэша и обновляет индекс.
